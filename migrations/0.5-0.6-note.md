- `docsys upgrade` prints the plan; `docsys upgrade --apply --commit` moves the
  tree in one commit. The items it lists for a person are theirs to finish.
- The git gate becomes hard on every tree, and a pull request's check reads
  only what the change does: an error its base already carries is named as
  inherited, with the base's commit, and blocks nothing; an error the change
  adds blocks, in the commit and in the pull request alike (D-136).
- A region that merged changes moved, each of which re-read the text it
  brought, is reported, not an error, naming the changes, until a re-read
  acknowledges the combination; the next pull request that moves the region
  or its page must re-read it. A change that moved a region without a re-read
  is still an error, and names that change (R-111, D-135).
- A code-side `doc:` counts after a comment leader or opening inline code
  (`` `doc: id` ``); one that only opens a line's text is prose from here on,
  so an object key or a typed field is no citation. The plan lists each
  citation that changes meaning (R-072, D-137).
- Where CI installs docsys from its release, the tree gets one installer,
  `.docsys-install` beside `.docsys-version`, which holds the version and its
  archives' sha256 values: CI runs it, and so does a clone with no docsys.
  The workflow's pull request job runs the scoped gate alone, push runs on the
  default branch only, and a merge queue is checked; in a workflow you edited,
  only those lines change, and the plan shows the diff (D-138).
