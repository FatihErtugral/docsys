# Implementation decisions register (R-193)

Where SPEC.md deliberately leaves a decision to the implementation, the decision
is made here, once, and the corpus enforces it. A future spec release may fold a
line back into rule text; until then this file is the authority for `docsys`.

| # | Decision |
|---|---|
| D-001 | **Zero runtime dependencies.** The binary is stdlib-only: auditable, no supply chain, instant builds. Revisit only if a check becomes impossible without a dependency. |
| D-002 | **Frontmatter YAML subset.** `---` fences; `key: value` scalars (optional quotes, ` #` comments); inline `[a, b]` and block `- item` lists; keys `[a-z][a-z0-9_]*`. Nesting, multi-line scalars, anchors and duplicate keys are parse findings, never guesses. `.docmeta.yml` is the same subset without the fences, plus whole-line `#` comments — a configuration file nobody can annotate is one people copy without understanding. An inline list reflowed across lines by a formatter is followed to its closing bracket: a real tree runs prettier over its markdown and YAML, and a field silently lost to reformatting disables a check without saying so (found when a reflowed `scan_exclude` brought back four resolved errors). |
| D-003 | **Ledger format.** `.tombstones.yml` entries open with `- id: <local-id>`; `date:` and `superseded_by:` continuation lines are tolerated (v0 reads only the id). |
| D-004 | **Dates.** `updated` and all spec dates are plain ISO `YYYY-MM-DD`; no time, no timezone. History-derived freshness (R-106) is deferred to the VCS-aware release. |
| D-005 | **Exit codes.** 0 = clean or warnings only; 1 = at least one error finding; 2 = tree not operable (missing root or `.docmeta.yml`). |
| D-006 | **v0 profile scope.** `profile: project` only. `knowledge-base` is recognized and reported as not-yet-implemented, never half-checked. |
| D-007 | **`_archive/` scope.** v0 does not walk `_archive/` at all: its pages join no check population; wiki-link targets are resolved against it by direct path probe only (R-071's resolve-and-report). |
| D-008 | **`defines:` glob subset.** A single trailing `*` (prefix match). R-079 token membership requires the cited identifier to occur token-bounded on the defining page (`-` counts as a word character). |
| D-009 | **Reachability edges (R-034).** Edges are wiki-links; the walk starts at `index.md` and follows through any non-archived page, transitively. |
| D-010 | **Finding subjects (R-158).** Per rule: reference checks → the target token; frontmatter checks → the field name(s), comma-joined; line-anchored format checks → `line-N` / `entry-N`; tree-level findings → file `-`. |
| D-011 | **Expected-output format.** Corpus cases carry `expected.tsv`: one finding per line, `SEVERITY<TAB>RULE<TAB>FILE<TAB>SUBJECT`, sorted; a first line `EXIT<TAB>n` asserts the exit class. Comparison is exact set equality — extra findings fail the case as hard as missing ones. |
| D-012 | **Code scanning (R-077) not offered in v0.** `doc:` references are resolved inside the documentation tree only; the `refs` command brings the code scan and R-072 with it. |
| D-013 | **Router acceptance.** `- [[<path>|<title>]] -- <sentence>` with ` -- ` canonical; a spaced em dash is accepted on read, never emitted. |
| D-014 | **Router-entry detection.** Only `- ` lines containing `[[` are entries subject to R-035's grammar; plain bullets are prose, and whether prose belongs on a router is judgment (first pilot: three false positives on layout-description bullets). |
| D-015 | **Backtick strip.** The backtick joined R-073's trailing-punctuation set (folded back into the spec): `` `doc: x` `` written as inline code is the reference convention of a real field tree. |
| D-016 | **Brownfield signal.** A tree whose markdown files all sit outside the layout — a router counts as inside — warns under R-020 (`layout`): an unmigrated tree must not read as a clean one (second pilot: 63 flat files, four findings, misleading silence). |
| D-017 | **Migration plan format.** `path<TAB>target` rows, target ∈ reference/howto/explanation/tutorial/archive/keep; `#` comment lines carry classification evidence (first heading, in/out link counts). The tool never fills a target — classification is judgment (R-003). |
| D-018 | **Migrated identifiers.** `id` derives from the filename in kebab-case (`AppManifests.md` → `app-manifests`); `type` is the plan's target; `updated` is the migration date. |
| D-019 | **Out-of-tree links survive migration.** A relative link escaping the docs root is depth-corrected to keep pointing where it pointed (R-172: the migration rewrites what its own moves invalidated) — and is then judged by lint on its own merits, which surfaces pre-existing R-075 debt instead of silently breaking or hiding it. |
| D-020 | **Inbound repo references.** `--repo` extends migration to the other side of the boundary: inventory reports every file referencing into the docs tree (Phase A risk report), apply rewrites exact moved-path strings across the repo — including inside URLs that carry the repo's own paths — and reports what it could not map (directory-level and generated-path references) as RISK lines for judgment. A match preceded by `/` or a word character is someone else's path, never rewritten, never a risk. |
| D-021 | **`refs` scope.** The code scan covers every readable text file in the repo minus the docs tree (lint owns that side), minus `scan_exclude` prefixes from `.docmeta.yml` (R-077 — the owner's word on archived sub-projects and tooling). Token grammar and resolution are byte-identical with the docs-side check: one shared index, one shared tokenizer, so the two sides can never disagree. Supersedes D-012. |
| D-022 | **Agent text rendering (R-155).** SPEC.md is embedded in the binary at build time; `rules --procedures` extracts §14.3 verbatim, `rules --agents-md` derives the always-loaded block mechanically (every `agent` rule's number + first sentence, the R-057 pattern) plus fixed tool-gate lines. Nothing is hand-authored, so the text cannot drift from the spec. The budget floor (R-165) is the rendered summary itself. |
| D-023 | **Agent assets (`docsys agents`).** Four hooks (pre-commit surface warning, stop reminder, updated-bump, session-intent routing), /doc-sync command, and the thin skill install under `.claude/`; every hook warns and never blocks (R-150), names what must change (R-152), and carries its edit-with-the-tree pattern note (R-011's dead-scan lesson). settings.json is printed for hand-merge, never written — it is a protected file. |
| D-024 | **Graduation plan format.** `# source:` header; per-block evidence comments (`# block <n> · L<a>-L<b> · fnv:<16hex> · "snippet"`); rows `<n><TAB>keep|link:<dest>|move:<dest>`. The fnv checksum is plan integrity, not the R-113 content hash: any drift between plan and apply refuses with "re-plan". `move:` destinations must pre-exist with an id (R-099's authored step is never done blindly); template-section headings stay in the source (R-098) and only bodies move; `graduated_to` is updated in place and may sit on an `active` file (R-091). |
| D-025 | **Heading map — universal, zero embedded languages.** `.docmeta.yml` `headings: [Context=<local form>, Decision=<local form>, ...]` declares the displayed form of each canonical template heading — the value is an arbitrary string, any script, any language; lint (R-048) and graduation keep-heading detection match through the map. The tool translates nothing and knows no language — the tree declares its own. |
| D-026 | **Universal adoption of an existing agent layer.** docsys assets use never-colliding names (`commands/docsys-sync.md`, `skills/docsys/`); the AGENTS.md block lives between `docsys:rules` markers and is updated idempotently, owner prose untouched; `agents --report` mechanically inventories the existing layer and the shell commands it invokes. Detection is the tool's; deciding what to delegate stays judgment — the tool never rewrites an owner's file (the first real integration was hand surgery; this decision makes it a supported flow). |

| D-027 | **A relative `--root` is anchored to `--repo`, and the docs-root exclusion holds by identity, not spelling.** `docsys refs --repo . --root docs` once walked `./docs/...` while excluding the literal `docs` — the docs tree was scanned as code and flooded refs with its own ids (+226 phantom errors on a real pilot). Two-layer fix: commands join a relative root onto the repo, and the repo walk compares the canonicalized docs root, so `./docs`, `docs`, and a symlinked spelling are all the same tree. `adopt` writes ADOPTION.md into the repo root by design: it carries no `doc:` tokens or `id:` frontmatter, so it cannot feed back into the gates. |
| D-028 | **Adoption settings and the extensions file.** `adopt` writes `.claude/settings.json` only when the file is absent (zero clobber risk); an existing file may carry MCP servers and permission/deny lists, so the merge snippet goes onto the ADOPTION.md checklist instead. Project-specific doc conventions split out during adoption land in `.claude/rules/doc-extensions.md` — a language-neutral conventional name; the file's *content* stays in the project's language. |

| D-030 | **Knowledge-base profile implementation** (supersedes D-006 — both profiles are now checked). Shaped by the first real knowledge base: a personal wiki whose constitution predated the spec and matches it. The root router is `wiki/index.md` and the domain indexes (`wiki/<domain>/index.md`) are routers too — R-035 grammar applies to every router. Wiki-links resolve against the permanent layer root: `[[<domain>/<type>/<page>]]` is the field convention, and `raw/` files are evidence, never link targets. `raw/**` is the profile's record layer for citation severity (R-194): a dangling link or reference in a raw note is reported, never blocked, and the path scan skips raw notes wholesale — they are quoted source material. The R-028 verification record is `verified_by:` (free text: person, session, or model) and `verified_rev:` (the VCS revision of the sources at verification). `sources:` entries are root-relative paths; entries carrying `://` are out of scope for R-059. `scan_exclude` prefixes exclude files from the docs-side walk as well as the repo scan — a template library inside a knowledge base is tooling, not documentation. |
| D-031 | **R-023 is checked at the gate.** Content-immutability has no observable baseline except the git working tree: lint reports uncommitted modification (`M`/`T`) or deletion (`D`) of tracked `raw/` files — deletion is excused when the basename reappears under `raw/` (relocation, R-023's expected flow; R-059 independently catches a severed `sources:` trail). An added-but-uncommitted file is not yet a record and stays mutable. Outside a git repository the check is inapplicable and the hook layer owns the promise. History rewrites are out of scope — a record that survived into history is the VCS's to protect. |
| D-032 | **The product map and `export product` (the local half of the product goal).** The map is plain markdown living **outside** the docs root: H1 product name, intro prose, H2 sections, and R-035-shaped entries whose targets are `doc:` identifiers, not paths — the docs-side link checks must never read them as links. `export plan` drafts a map from the tree's evidence (R-057 titles and summaries, grouped by type); keeping, cutting and naming sections is judgment (R-003). Composition is fully mechanical and refuses to half-compose: a foreign (`@ns/`), flowing, retired, or unknown identifier fails the whole run with the complete list — a product document with silently missing sections is the lie R-151 forbids. Bodies are carried verbatim with headings shifted two levels (fences untouched, prose never rewritten — the graduation principle applied to rendering); each composed page carries a source stamp: identifier, file, an FNV-1a drift hash (not the R-113 canonical hash — that arrives with the manifest), and `updated`. An `internal: true` page on the map composes **with a warning**: confidentiality is the channel's property (R-019) and the choice is the publisher's. Language: the tool determines none (R-120's note) and translates nothing — with `--lang` every composed page whose *declared* language (`lang:`, else `default_content_language`) differs from the intent is warned by name; without it a composition mixing declared languages is warned once. Translation is agent work (R-122/R-123), and a page whose declaration lies is invisible to this — declare `lang:` where the prose differs from the default. `export feature <id>…` composes a slice with no map file — the named identifiers, widened one mechanical hop along their wiki-links with `--follow` (a transitive closure would quietly become the whole tree, which is a map's decision, not a flag's). Regeneration is stateless by design — a cache is state and state drifts (R-002) — but `--out` writes only when the content actually changed (compared without the dated header line), so an unchanged document keeps its file, its generation date, and its downstream consumers untouched. |
| D-033 | **Audience is declared, never guessed.** A page may declare `audience:` (an export-layer convention; spec text arrives with the export section); the vocabulary is the tree's own, declared as `audiences:` in `.docmeta.yml` — the domains/R-026 pattern, so a misspelling is visible. An undeclared page reads as `developer`: every existing tree is developer documentation, so the default costs no migration and an audience-filtered export only ever includes a page that says who it is for. Filtering semantics: a page *named* on a map or command line with the wrong audience is refused (half-composing another reader's page in is the R-151 lie); a page reached by `--follow` with the wrong audience is a **named gap warning** — the walk found related material this reader cannot use, and authoring the counterpart is agent work. `export plan --audience <x>` drafts only declaring pages; zero pages is an error naming the whole-tree gap. The tool never writes and never re-audiences prose — the audience modes select, the agent authors. |
| D-034 | **Federation's first slice: fetch-direct over paths and git.** A consumer declares its providers in `.docmeta.yml` — at estate scale as ONE template plus names, `consume_base: "<template with {ns}>"` and `consume: [auth, billing, …]` (three hundred services must not mean three hundred hand-maintained locations, R-002); a `<namespace>=<location>` entry overrides the template per service. A location is a filesystem path or a git URL (`git@…`, `http(s)://…`, `ssh://…`, `file://…`, or ending `.git`) with an optional `#<subdir>` naming the docs root inside the repository (default `docs`); git providers are shallow-cloned into `.federation/.checkouts/<ns>` and hard-reset to the remote on every fetch — the cache is never edited, so the remote is always right. This settles the namespace-to-location bootstrap §13 leaves open, for the single-estate case. `docsys fetch` reads each provider tree directly and materializes every exported page as reconstructed frontmatter (R-136: id/type/updated/lang/audience — derived, not the provider's bytes) plus verbatim body, with a provenance sidecar (R-149: namespace, id, hash, fetch date). `internal: true` pages are never materialized (R-135). Composition resolves `@ns/<id>` only against this local state (R-148): unfetched → refusal naming the `consume:` line and `docsys fetch`; a body that no longer hashes to its sidecar → refusal (R-137). The v1 hash is FNV-1a 64 — drift detection between one user's own repositories, not tamper resistance; the R-113 canonical hash algorithm and the serialized manifest format stay open until the real cross-machine release, exactly as §13's experimental note predicts. Stamps on foreign sections carry the fetch date, so a stale composition is visible (R-148's age report). |
| D-035 | **An indented code block is quoted material.** Reference and path scanning skips fenced code and blockquotes; a CommonMark indented code block — four-plus spaces (or a tab) opening after a blank line — is the same thing in the other spelling, and a real knowledge base writes its `doc:`-citation examples that way. Found when an explanation page teaching the citation form had its own indented example read as a dangling reference (the exact self-reference trap R-073 already fixed for inline code). The block stays open across blank lines until a non-indented line, matching CommonMark. |
| D-036 | **A personal knowledge base stands up in two commands.** `init --profile knowledge-base` writes the record layer (`raw/inbox/`), the wiki root with its router, and a `.docmeta.yml` whose `domains:` the owner fills in; `agents --kb` installs the base's four organs as skills — capture (writes to the inbox, classifies nothing), ingest (distils a note into a wiki page, archives the source, routes it), audit (verifies against sources in another session, records or demotes), lookup (answers with the page path, or says the base does not have it) — plus an `AGENTS.md` constitution written only when absent. The skills carry judgment only; every mechanical rule they name is checked by the binary. Without this the tree was hand-assembled and the agent layer was somebody's private files, which is the adoption friction R-150 warns about at the level of a whole system. |
| D-037 | **A wiki-link target containing `<`, `>`, `{` or `}` is a placeholder, not a link.** R-073's rule for `doc:` references, applied to links: prose (or a generated skeleton) showing the router form cites nothing. Found by the tool's own knowledge-base skeleton, whose commented example failed the check it shipped with — the same self-reference trap that produced R-073 and D-035. |
| D-038 | **The manifest is the index, and fetch reads it first.** A publisher runs `export manifest` and ships `manifest.docsys` beside its docs root: format version, namespace, spec, and per identifier — type, title, summary, content hash, `updated`, optional lang/audience/owner, and the page's path — plus a `state: withdrawn` line per tombstone (R-133), with `internal: true` pages excluded entirely (R-135) and no bodies (R-134; title and the one-sentence summary are identity metadata, the deliberate exception). A consumer's `fetch` reads it before any body: a page whose published hash equals the provenance it already holds is skipped, keeping its bytes and its fetch date, so at estate scale a nightly refresh moves only what actually changed. The format is a line grammar, not JSON — it parses with the reader this binary already has, and a hand-readable manifest is one a human can diff in review. Its version is independent of the spec (R-180); an unimplemented MAJOR is refused by name, never silently skipped (R-182). A provider that publishes no manifest is still consumable: the tree itself is the index, which is what the first slice did. |
| D-039 | **The debt lifecycle** (owner's decision, field-shaped). `work/debt.md` holds LIVE debt only: an open item opens with its date — `- [ ] YYYY-MM-DD <debt> -- deferred: … -- repay when: …` — so its age is measurable (an undated open item is reported); a **repaid item leaves the file** — a `- [x]` line is reported with "delete it, record the repayment as a journal line": the journal is the chronology, git is the history, and a ledger of closed items is a second archive nobody reads. The dangling promise is checked: a page routing the reader to `work/debt` while the file declares no open item is reported — found live, when a journal entry pointed at the debt file for "what is still unproven" and the file read "None open." |
| D-040 | **The pipeline must be able to prove itself alive.** Field report: five compliance mechanisms silently failed at once — a hook on disk wired to nothing, a gate block dead below `exec`, warn output on channels the model never reads — and a fully broken pipeline was indistinguishable from a healthy one. Three answers. `docsys doctor`:every  piece checked for existing, executable, wired under the RIGHT event, and reachable (a docsys block below a top-level exec/exit is named as dead code — the exact shape found twice in one day). `docsys gate`: the commit-time question the binary computes — lint findings plus "changes outside the docs root with none inside" (staged; working tree when nothing is staged yet). ONE channel blocks — the PreToolUse hook, where exit 2 stops the call and the model reads stderr: lint errors block outright (severity doctrine), and the code-without-docs question ASKS ONCE — first attempt stops with the question, the same commit re-run proceeds. This refines R-150, not repeals it: a wall gets hooks disabled; a question does not, and a system whose every signal is invisible is the silent wrongness R-151 exists for. |
| D-041 | **The stop reminder reads the commits not yet pushed, not only the tree.** Field report: a session that commits as it goes ("gates green → commit and push is free") leaves a clean working tree at every turn end, so a reminder that read `git status` alone stayed silent through seven code-only commits. The Stop hook now unions the working tree with `@{u}..HEAD` (nothing extra without an upstream) and names the unpushed range when it speaks; it still warns and never blocks (R-150 — Stop output is not an enforcement channel, D-040). Same fix reads a rename's NEW path (`R old -> new`), where `awk '{print $2}'` read the old side. **Deferred, with its trigger:** a per-repository contract surface (glob list in `.docmeta.yml` that turns the pre-commit question into a deny with a `docs:ok=<reason>` escape). Not added: the ask-once question held 7/7 in the first measured session and a block without evidence is what gets hooks disabled (R-150/R-151). Repay when a repository on the ask-once gate lands a commit that changes its contract surface with no docs change within two weeks of adoption. |
| D-042 | **A wiki-link addresses a page, never a heading.** Field report: six `[[reference/x#section]]` links in one adopted tree were reported as dangling (R-071, error) while every page existed — the checker matched the whole target string against page paths, so a real page read as missing and the reader went looking for it; fourteen slug spellings were tried against the silence. Two answers were possible: resolve fragments (a heading-slug algorithm in the spec, deterministic across scripts, plus heading text becoming a second path-as-contract on top of the tension R-070 already notes and §19 defers), or say what the link form is. The spec now says it (R-070): the fragment is split off, the page part resolves, and a fragment on a resolved page is a warning that names the alias form `[[path|Title § Section]]`; an unresolved page part stays the R-071 error it was. **Deferred, with its trigger:** heading-level resolution. Repay when a second tree asks for section-level citation, or an aliased section label is found stale after a heading retitle — then it lands together with the identifier-based link form (§19). |
| D-043 | **The ask-once marker lives until HEAD moves, under the git dir.** Field report: an agent's commit shape is `git add … && git commit` — staging inside the command, after the PreToolUse hook has run against an empty index. The first attempt asked; a bare `git commit` then passed, committed nothing, and *consumed* the marker; the real attempt asked again, and "run the same commit again" was a promise the hook could not keep. Refines D-040: the key is (HEAD, staged set — or the working-tree set when nothing is staged, the scope the gate itself answered), the marker is kept on a pass and pruned when HEAD changes (a landed commit renews the key by construction), and it lives in `<git-dir>/docsys-gate/` — per repository, no `TMPDIR` dependence, nothing left behind in the system temp. Locked by an executed-hook test that replays the live sequence. |
| D-044 | **Deferred: untracked files in the gate's working-tree scope.** When nothing is staged the gate reads `git diff --name-only` — tracked files only — so a brand-new source file committed as `git add X && git commit` passes the commit-time question unasked (the Stop reminder still sees it, via `git status`). The candidate fix, `git ls-files --others --exclude-standard` in that scope, is not taken: its noise risk (build outputs outside `.gitignore`, a fresh adoption's stray files) is exactly the phantom-finding failure D-029 records, and there is no measured case yet. Repay when the Stop reminder catches a new source file that landed without documentation at least once — the reminder counts, and the count decides. |
| D-045 | **A `scan_exclude` entry is a path prefix, and one the prefix form cannot express is reported.** Field report: `spec/**`, `./spec/**`, `**/spec/**` in an adopted tree excluded nothing and said nothing — eleven findings stayed, and only the bare `spec` worked. The spellings of "this directory" (`spec`, `spec/`, `./spec`, `spec/**`) now reduce to the same prefix, matched on a component boundary (`spec` never excludes `specification.md`); glob syntax and parent steps are a warning under R-077 naming the entry and the form. Not taken: a glob engine — a dependency-free matcher is a second grammar to specify and conform, for a key whose real use is "this directory". Repay when a tree needs an exclusion a prefix cannot name (a file pattern across directories) — then the engine, with its conformance case. |
| D-046 | **A generated report keeps the owner's leading comment block.** Field report: a privacy classifier stamps every `.md` with a marker comment at the top; `adopt` rewrote `ADOPTION.md` and the marker was gone on every run, in four trees. The leading HTML-comment block (blank lines inside it included) is the owner's and survives regeneration; everything after it is the generator's. The same rule applies to any file docsys regenerates in place. |
| D-047 | **Hooks carry the template version they were written from.** `adopt` keeps an existing hook (an owner may have edited it), so a tree that adopted once never received a later template — the ask-once fix in 0.4.4 reached four trees only through a hand-written `agents --force` step. Every hook now carries `# docsys-template: <version>` under its shebang; `adopt` and `doctor` name the hooks behind the binary (or unversioned) and the command that refreshes them. Information, not failure: a stale hook still runs. |
| D-029 | **Inside a git repository, git enumerates the files to scan.** `refs` (and every repo-side scan) lists files with `git ls-files --cached --others --exclude-standard`, so `.gitignore` is the single source of truth for what belongs to the project; the directory walk with its built-in skip list remains the fallback outside a git repository. Forced by the first real-repo adoption: a hand-maintained skip list cannot predict build outputs, vendored trees, or nested worktrees — the pilot repository kept git worktrees under a dot-directory, and scanning them produced 9,171 findings where 147 were real (98% phantom). A checker that reports thousands of untrue findings is worse than no checker: it teaches people to ignore it (R-150). |
| D-048 | **Paths cross the git boundary unquoted.** Field measurement with a non-ASCII page name: git writes `"docs/g\303\274nl\303\274k.md"` under its default `core.quotePath`, no docs-root prefix matches a quoted path, and so a real documentation change was read as a code change — the gate asked, the stop reminder warned, and a tree whose pages carry names in its own language could never answer the question. Every git call whose output is compared against a path passes `-c core.quotePath=false` (the binary's gate, the hook templates); the hooks match the docs root with a shell `case` pattern, not a regex built from the root's text. The same pass fixed the PreToolUse hook reading the command out of the JSON payload at the first quote, escaped or not — `printf "x" > y && git commit` was never gated. The tool is language-neutral by design (D-025); a path is the first place that neutrality is tested. |
| D-049 | **A blocked call is blocked whole, and the hook says so.** Field report: `git add -A && git commit …` was stopped by the PreToolUse question; the agent retried a bare `git commit`; the index still held an earlier `git rm --cached`, so a commit whose message told the whole story landed with six deletions as its content — and a fresh clone's `make check` fell at the first gate while ten local gates stayed green, because gates read the working tree and consumers read HEAD. Three answers. The refusal names the mechanism ("this whole Bash call was blocked — a `git add` in it did not run either; re-run the same command from the start"). The marker records whether the blocked call carried a `git add`; a retry without one, while the tree still holds unstaged changes, is stopped once more with the question "did your `git add` run?" — once, like the question itself, and never for a commit that was bare from the start. The generated AGENTS block carries the one sentence that generalizes it: what landed is `git show HEAD:<file>`, not the tree. |
| D-050 | **The commit gate matches command lines, not heredoc bodies.** Field report: a rule text written through `cat <<'EOF' … EOF` quoted the words "git commit" and the PreToolUse gate fired on a call that committed nothing — harmless under ask-once, but a false positive teaches people the gate is noise (R-150). The hook opens the payload's `\\n` escapes and drops every line between `<<WORD` and its terminator before matching; the heredoc line itself stays, because `git commit -F - <<'MSG'` is a commit. Quoted strings on a command line (`-m "… git commit …"`) are still matched — cheap to stop at, and a false positive there costs one re-run. Locked by executed-hook tests: body-only → not gated; heredoc-fed commit → gated; commit after a heredoc → gated. |
| D-051 | **The hook logic lives in the binary; the installed scripts relay.** One day of pilot reports, all in the shell relay: a payload read with `grep` stopped at an escaped quote, a heredoc body passed for a command, a `\\t` never opened, a path quoted by git. The shell has no JSON parser and cannot be unit-tested; the binary has both. `docsys hook <event>` now makes every decision — a real JSON parser for the payload, heredoc-aware command detection, unquoted git paths, the ask-once marker, the stop reminder's scope, the `updated:` bump, the routing text — and each is pinned by unit tests and a payload table. The four scripts `docsys agents` installs are `command -v docsys || exit 0; exec docsys hook <event>` — nothing left in them to get wrong; `docsys` absent means the hook is silent, as before. |
| D-052 | **The debt ledger holds items only; prose after the first item is an error.** Field measurement on a pilot ledger, 201 commits deep: zero `- [x]` lines survived (the D-039 warning was read and acted on), yet 14% of the file was prose — three "closed" sections written where deleted items had been, an open debt written as a heading, and the owner had asked for the list to be cleaned more than once. Every check read only the checkbox lines, so the ledger passed clean.
